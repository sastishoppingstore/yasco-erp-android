================================================================================
PART 0 — EXECUTIVE VERDICT
================================================================================

The ERP has TWO PARALLEL ZATCA IMPLEMENTATIONS:

  (A) REAL INVOICE FLOW  (what actually runs)
      api/salesRouter.ts, api/posRouter.ts, api/syncRouter.ts,
      api/zatcaCompleteRouter.ts, api/decorationRouter.ts
      -> Phase-1 grade only: 5-tag TLV QR, minimal XML, no UUID,
         no PIH/ICV, no XAdES signature. NOT ZATCA Phase 2 compliant.

  (B) ADVANCED LIBRARY  (what should run, but is never called)
      api/lib/zatca/xmlBuilder.ts, signingEngine.ts, hashChain.ts,
      certificates.ts, onboarding.ts, clearance.ts, validator.ts,
      archiving.ts, pdfGenerator.ts
      -> Contains the correct concepts but several algorithms are wrong
         (PIH seed, pseudo-signature, incomplete CSR) and no router uses it.

RESULT: The system cannot pass a single ZATCA Phase 2 compliance test in its
current wiring. Estimated readiness: 25–35% for Phase 2, ~85% for Saudi HR.

Ready  : 15% VAT data model, bilingual A4 invoice template, RTL framework,
         GOSI / WPS / EOSB / Iqama / Qiwa, encrypted credential storage,
         offline mutation queue, real ZATCA endpoints + Accept-Version V2.
Remains: invoice UUID, UBL export, PIH/ICV chain, XAdES ECDSA signing,
         compliant CSR/CSID onboarding, 9-tag QR, working clearance/reporting,
         credit/debit notes, POS + offline QR, pre-submission validation,
         immutability locks, Riyadh timezone, payment gateways.

================================================================================
2.1 CRITICAL FAULTS & COMPLIANCE BLOCKERS
    (each one will fail ZATCA Compliance Testing)
================================================================================

--------------------------------------------------------------------------------
[C-01] The invoice table cannot store a Phase 2 invoice
--------------------------------------------------------------------------------
File : db/schema.ts  L826-870
Fault: `invoices` has zatcaQrCode / zatcaXml / zatcaStatus but NO:
       uuid, invoiceHash, previousInvoiceHash, icv, signedXml,
       submissionStatus, clearedAt, reportedAt, qrPhase2.
Impact: There is nowhere to persist the mandatory Phase 2 identity of an
        invoice. Restarting the app or re-printing loses the legal record.
        ZATCA audit (6-year retention) impossible.
Severity: BLOCKER.

--------------------------------------------------------------------------------
[C-02] The XML that is actually generated is not valid UBL 2.1
--------------------------------------------------------------------------------
File : api/salesRouter.ts  L42-71  (buildSaudiInvoiceXml)
        api/zatcaRouter.ts L205-265 (inline XML)
Fault:
  * No `cac:AccountingCustomerParty` (buyer) at all.
  * No `cac:InvoiceLine` elements -> line totals cannot be validated.
  * No `cac:TaxTotal/cac:TaxSubtotal` with taxable amount + category.
  * No `cbc:IssueTime`.
  * `InvoiceTypeCode name="0100000"` hardcoded, so B2C simplified invoices
    are exported as standard B2B (wrong subtype 0100000 vs 0200000).
  * No UUID, PIH, ICV, QR, signature extension.
Impact: Fails BR-02, BR-06, BR-CO-10..15, BR-S-08..09, KSA-2/4/5 rules.
Severity: BLOCKER.

--------------------------------------------------------------------------------
[C-03] QR code is Phase 1 (5 tags), not Phase 2 (9 tags)
--------------------------------------------------------------------------------
File : api/salesRouter.ts L24-47 (encoder), L536-541 (use),
       api/taxComplianceRouter.ts L77,
       api/zatcaCompleteRouter.ts L302
Fault: Only tags 1-5 are emitted. Missing:
       Tag 6 = SHA-256 XML hash (base64)
       Tag 7 = ECDSA signature
       Tag 8 = public key
       Tag 9 = ZATCA stamp (B2B clearance)
       api/zatcaRouter.ts L718 fills 7-9 with placeholder strings.
Impact: Every QR printed on a B2B invoice is non-compliant; B2C QR lacks
        hash/signature verification. ZATCA scanner rejects it.
Severity: BLOCKER.

--------------------------------------------------------------------------------
[C-04] PIH and ICV chain is mathematically wrong and unused
--------------------------------------------------------------------------------
File : api/lib/zatca/hashChain.ts  L6, L22-26
Fault:
  * L6  EMPTY_HASH = SHA-256("") ; must be base64(SHA-256("0")).
  * L24 PIH = SHA-256(prev + current) ; must be exactly `prev`.
  * No sequential ICV allocation, no per-device counter, no transaction.
  * Called by nobody.
Impact: Chain verification fails from invoice #1 onward.
Severity: BLOCKER.

--------------------------------------------------------------------------------
[C-05] Signing is not a ZATCA signature at all
--------------------------------------------------------------------------------
File : api/lib/zatca/signingEngine.ts  (whole file)
       api/lib/zatca/xmlBuilder.ts     L518-586 (wrapWithExtensions)
       api/zatcaRouter.ts              L205-265 (pseudo signature)
Fault:
  * `createSign("sha256")` over the entire XML string, no C14N 1.1.
  * No `<xades:SignedProperties>` digest (the legal ZATCA requirement).
  * `certificateHash` computed from the PRIVATE KEY (L22-24).
  * Public key pushed into tag 8 raw, not the X.509 certificate.
  * `api/zatcaRouter.ts` writes a decorative `<Signature>` block that is not
    cryptographically bound to the document.
Impact: Signature verification fails; tamper-evidence absent.
Severity: BLOCKER.

--------------------------------------------------------------------------------
[C-06] CSR is not a ZATCA CSR -> onboarding will be rejected
--------------------------------------------------------------------------------
File : api/lib/zatca/certificates.ts L128-196
       api/lib/zatca/onboarding.ts   L100-105
Fault: Subject has only CN / O / C (and optionally SN/UID/email).
       Missing mandatory ZATCA attributes:
         OU, title = "1100", 15-digit UID (starts and ends with 3),
         registered address, business category,
         and the ZATCA custom OID extensions.
Impact: `POST /compliance` rejects the CSR; no CCSID -> no PCSID.
Severity: BLOCKER.

--------------------------------------------------------------------------------
[C-07] Compliance Testing is simulated locally, never sent to ZATCA
--------------------------------------------------------------------------------
File : api/lib/zatca/onboarding.ts L236-265 (recordComplianceTestResult)
       api/zatcaRouter.ts        L790-805 (readiness payload)
       api/taxComplianceRouter.ts L507-619
Fault: Results are written to local arrays/tables; no HTTP call to the
       ZATCA compliance endpoint. `completeOnboarding` accepts a PCSID PEM
       as plain input instead of exchanging a CCSID.
Impact: Solution-provider / device onboarding cannot be approved.
Severity: BLOCKER.

--------------------------------------------------------------------------------
[C-08] Clearance/ Reporting worker crashes at runtime
--------------------------------------------------------------------------------
File : api/queue/tax.queue.ts L30, L36
       api/lib/zatca/clearance.ts L108-114

Impact: Any ZATCA job throws TypeError / undefined. Live submission is dead.
Severity: BLOCKER.

[C-09] Credit / Debit notes are not e-invoices
--------------------------------------------------------------------------------
File : api/salesRouter.ts L1109-1180 (creditNoteCreate)

[C-12] ZATCA HTTP responses are collapsed incorrectly (200/202/400)
--------------------------------------------------------------------------------
File : api/lib/zatca/clearance.ts L192-250

[C-13] No database-level immutability; UI guards are bypassable

================================================================================
2.2 WARNINGS & EDGE-CASE BUGS
================================================================================

[W-01] Rounding is float-based, no decimal library, no reconciliation
  Files: api/lib/zatca/xmlBuilder.ts L92 (`amount.toFixed(2)`),
         api/lib/zatca/completeImplementation.ts L190-238,
         api/posRouter.ts L155 (`toFixed(4)`),
         api/salesRouter.ts L974 (`toFixed(2)`)
  Risk : 0.01 SAR drift between sum(lines) and header; no BR-CO-15 /
         BR-S-08 pre-check; `toFixed` on JS floats is not banker's rounding.
         Line tax is derived per-line then summed, but header tax comes from
         the client input (`invoiceData.taxAmount`) — the two can disagree.

[W-02] Tax categories Z / E / O exist only in the unused builder
  File: api/lib/zatca/xmlBuilder.ts L29, L121, L273, L314, L438
  Risk: The live flow always taxes at 15% (default `taxPercent = 15` in
        db/schema.ts L823, api/salesRouter.ts L862). Zero-rated / exempt /
        out-of-scope lines cannot be issued correctly.

[W-03] VAT validation is structural only
  Files: api/salesRouter.ts L85-88, completeImplementation.ts L290-293
  `^3\d{13}3$` — correct shape, but no check against the seller's registered
  number, no buyer VAT enforcement for B2B, no CR number validation.

[W-04] Saudi National Address is missing
  db/schema.ts `invoices` has only free-text customerAddress / customerAddressAr
  (L846-848). No building number, district, additional number, or postal code
  fields required by ZATCA Party address blocks.

[W-05] ICV race condition across branches/terminals
  api/zatcaRouter.ts `nextInvoiceCounter` (used at L191) is not transactional;
  no `SELECT ... FOR UPDATE`; no unique constraint on
  `(tenantId, invoiceUuid)` in zatca_invoice_status.
  Two simultaneous invoices -> same ICV -> chain corruption.

[W-06] Invoice-number uniqueness is per tenant only
  db/schema.ts L869 `inv_num_idx` on (tenantId, invoiceNumber).
  No uniqueness for UUID; no per-EGS-device sequence table.

[W-07] Dead / duplicate modules mislead maintainers
  * db/migrations/schema.ts contains a second `invoices` definition WITH
    uuid, invoiceHash, isLocked, localUuid — not imported anywhere but
    contradicts db/schema.ts (which drizzle.config.ts actually uses).
  * api/lib/zatca/index.ts re-exports all modules, including dead pdfGenerator.
  * api/lib/zatca/{archiving,validator,pdfGenerator,completeImplementation}
    are effectively unwired (validator: 0 callers; archiving: 0 callers).

[W-08] No automated ZATCA tests
  api/__tests__ contains only errors.test.ts. `api/lib/zatca/testingScript.ts`
  is manual and not part of `npm test`.

[W-09] Onboarding compliance test list is a local constant
  api/lib/zatca/onboarding.ts COMPLIANCE_TEST_INVOICES — never executed
  against the ZATCA sandbox.

[W-10] Queue retry constants declared but unused in the live path
  api/lib/zatca/clearance.ts L45-48 (MAX_RETRIES, backoff) — the worker
  (api/queue/tax.queue.ts) crashes before reaching retry logic.

[W-11] Encryption key handling
  api/lib/zatca/certificates.ts L30-55 derives the AES key from an env value.
  No key rotation, no KMS/HSM; private keys sit in MySQL text columns.
  Acceptable for MVP, not for solution-provider certification.

[W-12] Thermal Arabic
  api/lib/thermal/escpos.ts L128, L171 use English labels only; no CP1256 /
  CP864 code page switch, so Arabic seller name will print as garbage.

[W-13] PDF "ZATCA Compliant" label is misleading
  api/services/pdfService.ts L208 prints "ZATCA Compliant" regardless of the
  actual QR content (which is Phase 1 only).

[W-14] POS ignores partial payments / multiple methods
  api/posRouter.ts L146-245 always `status: "paid"` and writes a single
  cashbox row; `balanceDue` computed with toFixed(4) but never stored as a
  distinct status.

[W-15] No retention/archival job
  api/lib/zatca/archiving.ts (6-year retention helpers) has zero callers.
